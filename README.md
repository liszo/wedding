# دعوت‌نامه‌ی عروسی — شقایق و رامین

A private, per-guest Persian wedding invitation. Every guest gets their own link, is
greeted by name, RSVPs once, and can post to a shared wall.

Next.js 16 (App Router) · Tailwind v4 · Supabase · Motion.

```bash
npm run dev      # http://localhost:3000
npm run assets   # regenerate public/design from design/ (only after changing artwork)
npm run build
npm run lint
```

## Where things live

| Path | What |
|---|---|
| `content/config.ts` | **Edit this first.** Names, date, venue, running order, dress code. Everything user-facing reads from it. |
| `content/story.ts` | The three story chapters: خواستگاری → بله‌برون → عروسی. |
| `content/photos.generated.ts` | Generated by `npm run assets` — do not hand-edit. |
| `design/` | The artwork library. `design/ASSETS.md` documents every file and the rules for using it. |
| `scripts/prepare-assets.ts` | Crops, desaturates and compresses the photographs; shrinks the stickers; writes the manifest. |
| `scripts/tokens.ts`, `scripts/seed-guests.ts` | Guest list and invite-link generation. |

## Visual system

Ivory paper, deep olive, antique gold. Tokens are defined once at the top of
`app/globals.css`, with a note on why gold exists in several weights — the ornament gold
`#A8935C` is 2.7:1 on paper and must never be used for text; `--gold-ink` is the readable
one on paper, `--gold-lite` the readable one on olive.

**Section division is the point of this design.** The page is one 430px column of
alternating paper and olive bands, and they never meet on a straight line:

| Piece | What it does |
|---|---|
| `<Band tone dome>` | a band; `dome` makes it swell 78px up over the one above, with a gold hairline following the curve |
| `<Scallop from to>` | a lace hem of the band *above*, hanging into the one below — four layers: the band below as background, the wave filled with the band above, a gold hairline tracing it, and a pearl at every cusp under the tiling gold lace |
| `<Seam src>` | a floral cutout pinned across the join, half on each band |
| `<SectionHead>` | eyebrow → ornament → nastaliq title → divider |
| `.pre-dome` | bottom padding for a band a dome overlaps, so full-width content clears the crest |

`<Scallop>` needs **both** tones. Its own background has to be the band below —
`.frame` is paper, so without that the transparent parts of the wave show paper and the
scallops are simply invisible on a paper-to-olive join.

One gotcha: `.band > *` sets `position: relative` so content clears the grain overlay.
`.band > .absolute` and `.band > .fixed` restore the utilities at higher specificity — an
absolutely-positioned child of a `<Band>` would otherwise be silently dropped back into
the flow.

Everything decorative goes through `components/ui.tsx`, which also holds the only two
maps of asset paths (`ORNAMENT`, `FLORAL`). The hero is full-bleed black and white; see
`design/ASSETS.md` for how that image is produced.

`lib/jalali.ts` builds the Persian month grid for the countdown section from
`wedding.dateISO` via `Intl`'s `persian` calendar — change the date and the grid follows,
including which weekday it starts on and whether Esfand has 29 days.

## Opening sequence

Two overlays, in order, both session-scoped so they appear once per visit:

1. **`<MusicGate>`** asks whether to play the soundtrack. It has to come first —
   browsers only allow `play()` during a user gesture, so `lib/music.ts` keeps the
   `<audio>` element in a module-level store and the gate calls `choose("yes")` straight
   from its own click handler, while that gesture still counts. The 4.7MB track is
   `preload="none"` until someone says yes.
2. **`<Envelope>`** — the wax-sealed gate. It waits for a music answer before rendering,
   so the two never stack or fight over focus.

## Guest flow

1. `scripts/tokens.ts` writes `guest-links.csv` — one `/i/<token>` URL per guest.
2. `/i/[token]` verifies the token, sets an HMAC-signed session cookie, redirects home.
   A bad or rate-limited token redirects with `?e=bad` / `?e=slow`, which `LinkNotice`
   renders as an explanation rather than a silent drop.
3. `/api/lookup` is the recovery path — a guest who lost their link enters their phone
   number and gets the session back.
4. `/admin` (password) shows every response and exports CSV.

Both `guests.csv` and `guest-links.csv` are gitignored. They contain real phone numbers.

## Images

Nothing goes through `next/image`. Every image is a static WebP that `npm run assets`
already cropped and compressed to its display size, with `width`/`height` set at the
call site so nothing reflows — 3.4MB of raw camera exports become ~720KB of view images
plus ~260KB of thumbnails, and the thumbnails are what the page actually loads. Guest
uploads on the wall are compressed in the browser (`lib/compress.ts`) before upload.
The `@next/next/no-img-element` rule is switched off in `eslint.config.mjs` for exactly
this reason.

## Environment

```
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
SESSION_SECRET=            # any long random string; signs the guest cookie
ADMIN_PASSWORD=
NEXT_PUBLIC_SITE_URL=      # optional; only needed if not deploying on Vercel
```

`NEXT_PUBLIC_SITE_URL` sets `metadataBase`, which is what makes the WhatsApp/Telegram
link preview resolve its image. On Vercel it is inferred from
`VERCEL_PROJECT_PRODUCTION_URL`.
